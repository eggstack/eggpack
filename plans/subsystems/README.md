# Subsystem Roadmaps

Subsystem roadmaps translate canonical Eggpack direction into coherent dependency-aware workstreams. They are not direct coding-agent checklists.

Each roadmap must define ownership before milestones, classify invariant/capability/infrastructure/polish work, expose dependency gates, preserve milestone history, and link implementation/closure records.

Initial active roadmaps are intentionally limited to work that can already be reasoned about from Eggup and current Eggstack release evidence. Future specialized adapters should receive roadmaps only when dependencies and consumer evidence make them actionable.
